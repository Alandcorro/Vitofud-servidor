1. ¿Cómo funcionan los repositorios?

Piensa en un repositorio (o "repo") simplemente como una carpeta digital para tu proyecto.
• El historial de cambios: A diferencia de una carpeta normal en tu computadora, un repositorio guarda el historial de cada cambio que haces. Si borras algo por error, puedes "viajar en el tiempo" y recuperarlo.
• Tipos de repositorios:
	• Públicos: Todo el mundo en internet puede ver tu código (ideal para compartir o mostrar tu trabajo).
	• Privados: Solo tú (y las personas que tú elijas) pueden ver el contenido.

2. ¿Cómo borrar las apps, páginas web o archivos que subiste?

Si subiste una página o archivos y ya no quieres que estén en GitHub, tienes dos opciones dependiendo de si quieres borrar todo el proyecto o solo algunos archivos.

Opción A: Borrar un repositorio entero (Elimina toda la app o página)

1. Entra a GitHub y haz clic en el repositorio que quieres borrar.
2. En el menú de arriba del proyecto, haz clic en la pestaña Settings (Configuración) con el ícono de engranaje ⚙️.
3. Baja hasta el puro final de la página hasta encontrar la sección roja llamada "Danger Zone" (Zona de peligro).
4. Haz clic en el botón Delete this repository.
5. GitHub te pedirá escribir el nombre de tu usuario y del repositorio para confirmar que estás seguro. Haz clic en aceptar y se eliminará por completo.

Opción B: Borrar archivos específicos dentro de un repositorio

1. Entra al repositorio y busca el archivo que quieres quitar.
2. Haz clic sobre el archivo para abrirlo.
3. En la esquina superior derecha del archivo, haz clic en el ícono de los tres puntos (...) y selecciona Delete file (Eliminar archivo).
4. Al final de la página, haz clic en el botón verde Commit changes (Confirmar cambios) para guardar el borrado.

3. ¿Mis archivos al subirlos están "blindados"?

La respuesta corta es: Están muy seguros contra hackeos a los servidores de GitHub, pero depende 100% de la configuración que tú elijas.
• Seguridad de la plataforma: GitHub pertenece a Microsoft y utiliza infraestructura de seguridad empresarial. Nadie va a poder hackear sus servidores fácilmente para robar tus archivos.
• El peligro de los Repositorios Públicos: Si tu repositorio es Público, tus archivos no están blindados de las miradas de los demás. Cualquier persona puede verlos, descargarlos y copiarlos.
• 🚨 ¡Mucho cuidado con las contraseñas! Si subes un archivo que contiene contraseñas, claves de bases de datos o tokens secretos a un repositorio público, hay sistemas automatizados ("bots") que los escanean en segundos para robarlos.
Tu escudo de privacidad: Si quieres que tus archivos estén totalmente protegidos y ocultos de los ojos de los demás, asegúrate de cambiar la visibilidad del repositorio a Privado (puedes cambiar esto en la misma pestaña de Settings).

Las dos formas correctas de subirlo

Elige el método que te sea más cómodo según tus herramientas actuales:

Opción A: Directo desde la página web de GitHub (El método más visual)

1. Entra a tu cuenta en GitHub y crea un nuevo repositorio público llamado vitofud-servidor.
2. Una vez creado, busca la opción que dice "uploading an existing file" (subir un archivo existente).
3. Abre el explorador de archivos de tu computadora y entra a la carpeta principal de tu proyecto.
4. Selecciona todos los archivos y carpetas internos (como server.js, public, qr.js, etc.) y arrástralos directamente a la ventana del navegador.
5. Al final de la página, haz clic en el botón verde Commit changes para guardar la subida.

Opción B: Usando Git desde la consola de comandos

Si ya tienes Git instalado en tu computadora, abre la terminal dentro de la carpeta del proyecto y ejecuta estos comandos secuenciales:
1. git init (Inicia el repositorio local).
2. git add . (Prepara todos tus archivos sueltos para subirse).
3. git commit -m "Primer commit: Estructura base de VitoFud" (Guarda los cambios localmente).
4. git branch -M main (Nombra tu rama principal).
5. git remote add origin https://github.com (Vincula tu proyecto con la web).
6. git push -u origin main (Sube todo el código en limpio).

🚨 ¡Aviso crucial antes de subirlo! (La carpeta node_modules)

Si dentro de tu proyecto existe una carpeta llamada node_modules, NO la subas. Esa carpeta contiene miles de archivos pesados que descargó Node.js y que hacen que la subida sea lentísima.
• Cualquier programador que descargue tu proyecto solo necesita ejecutar tu archivo instalar.bat (o escribir npm install) para que esa carpeta se genere sola en su computadora.
• Si usas el método de la consola (Opción B), asegúrate de crear primero un archivo de texto llamado .gitignore y escribir adentro la palabra node_modules para que Git la ignore automáticamente.

# VitoFud - Servidor de Gestión Gastronómica 🍔🕒

**VitoFud** es un sistema backend robusto y eficiente diseñado para **gestionar pedidos y turnos en tiempo real para establecimientos de comida**. El proyecto resuelve un problema real del sector gastronómico: optimizar y coordinar la comunicación interna entre el cliente, la cocina y la caja desde cualquier dispositivo conectado.

El sistema permite que los clientes en las mesas realicen sus pedidos de forma autónoma, enviando la información instantáneamente a los paneles de preparación (cocina) y cobro (caja).

---

### ⚙️ Funcionalidades Principales

*   **Panel de Pedidos Interactivo:** Interfaz intuitiva para que el usuario arme su pedido y lo envíe al flujo de preparación.
*   **Pantalla de Cocina en Tiempo Real:** Visualización dinámica de los pedidos entrantes para los cocineros, permitiendo cambiar estados de preparación de manera eficiente.
*   **Control de Caja:** Interfaz dedicada para la administración, confirmación de cobros y cierre de transacciones.
*   **Automatización de Turnos:** Módulo integrado para la asignación y visualización clara de turnos de atención.
*   **Scripts de Automatización (.bat):** Inclusión de ejecutables nativos para automatizar la instalación de dependencias y el arranque del entorno local con un solo clic.

---

### 🛠️ Tecnologías Utilizadas

*   **Backend:** Node.js, Express.js
*   **Frontend:** JavaScript Vanilla (ES6+), HTML5, CSS3 (Estructura modular optimizada)
*   **Automatización:** Batch Scripts (`.bat` para Windows)

---

### 📂 Estructura del Proyecto

*   `/public`: Contiene las vistas independientes del sistema (`pedir.html`, `cocina.html`, `caja.html`, `turnos.html`) y los estilos globales.
*   `server.js`: Núcleo del servidor Express que coordina las peticiones y la lógica del negocio.
*   `comun.js`: Archivo compartido que centraliza las funciones del frontend y la comunicación con el servidor.
*   `instalar.bat` / `iniciar.bat`: Herramientas de automatización para despliegue rápido.

---

### 🚀 Instalación y Uso Local
